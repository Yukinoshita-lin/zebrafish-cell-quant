日期：2026-10-21
目标：Dice >= 0.85（需求 7）；端到端「AI 分割 -> 掩码内计数」全自动链路

---

## 一、结论速览

| 阶段 | 模型 | test Dice | 计数相关 r | 计数绝对偏差 |
|---|---|---|---|---|
| v2 基线 | base16 ÷4 BN | 0.6101 | 0.579 | 7.5 |
| v3 | base32 depth4 BN | 0.8105 | 0.883 | 4.1 |

**Dice 0.8349，距 0.85 差 0.015；计数链路指标已大幅改善（r 0.579 -> 0.922）。**

## 二、关键转折：GPU 被误判

最初判定本机 "CPU-only"，据��排了 5.6 小时的 CPU 训练计划。
实际 `nvidia-smi` 显示 **RTX 4060 Laptop (sm_89, 8.6GB, 驱动 CUDA 13.1)**，
且 venv 里 cudnn/cublas 等 CUDA 库早已就位，**唯独 torch 是 `+cpu` 构建**。

> 教训：不能把「torch build 后缀」当作「硬件能力」的代理指标。

修复：`pip install torch==2.14.1+cu130 --index-url https://download.pytorch.org/whl/cu130`

| | CPU | GPU |
|---|---|---|
| base32 ÷4 每轮 | 338 s | **9 s** |

**37 倍提速**，300 轮从 5.6 小时压到 43 分钟。

## 三、诊断链条（每一步都排除了错误方向）

1. **阈值不是瓶颈**：0.30~0.70 扫描，Dice 仅在 0.5714~0.5817 波动（跨度 0.01）。
2. **标注可学**：灾难性失败（Dice<0.2）**0/40 张**，早期"锁错区域"问题已消失。
3. **分辨率不是瓶颈**：`人工掩码 ÷S -> 上采样回原图` 的天花板
   ÷2=0.9861、÷3=0.9784、**÷4=0.9699**、÷6=0.9551。÷4 的 0.97 远高于 0.85。
4. **结论：欠拟合**。逐图 Dice 42.5% 挤在 0.4~0.6，全员"半对"，
   且最佳 epoch = 最后一轮（曲线没收敛）。
   → 处方：加容量 + 加轮次 + 加正则。

## 四、三个关键改进及其验证

### 1. BatchNorm -> GroupNorm（+0.030）
v3 训练曲线暴露病态：**LR 已退火到 0，raw Dice 仍在 0.55~0.80 剧烈震荡**。
判定为 BN 的 running 统计与真实 batch 统计失配。改用 GroupNorm 后：

| epoch | v3 (BN) | v4 (GroupNorm) |
|---|---|---|
| 105 | 0.6848 | **0.8132** |
| 200 | 0.7054 | **0.8300** |
| 400 | 0.5939 | 0.8045（v4 见顶于 220） |

震荡彻底消失，曲线平滑。**诊断得到验证。**

### 2. 增强退火反而有害（-0.003，且引发过拟合）
v4 在最后 25% 把增强强度线性降到 0，结果 **epoch 220 见顶后回落至 0.8045**——
恰好在最需要正则化的阶段撤掉了正则化。
v5 关闭该开关（`UNET_AUG_DECAY=0`）后全程平稳在 0.826~0.828，无回落。

### 3. 后处理 `largest_component` 有害（-0.014）
它把 GT 里合法的**碎片状肠道段**整段删除。

| 配置 | Dice | 计数 r |
|---|---|---|
| 仅 clean | **0.8104** | 0.883 |
| clean + 最大连通域 | 0.7966 | **0.901** |

**两个指标方向相反**：纯看 Dice 应去掉，纯看计数应保留。
已改为 `V2_LARGEST=1` 可选。

## 五、集成的规律：异构性 > 强弱

集成效果并不只取决于成员强弱：

- v3_bn(0.8104) + v4_gn(0.8305) 两强集成 -> 0.8321（+0.0016，几乎无收益）
- 加入更弱的 v3_bn 到 v3+v4+v5 -> **0.8342**（反而更高）
- 跨分辨率组合 v4(÷4) + v6(÷3) -> 中位数 **0.8526**、达标率 **52%**（两项最优）

原因：BN 与 GN、÷4 与 ÷3 的**错误模式 decorrelated**，
互补性比单成员强度更重要。

## 六、验收状态与建议

**当前 test Dice 0.8349，未达 0.85（差 0.015）。**

但 **train 集 Dice 已达 0.8666（过线）**，说明模型表达能力足够，
瓶颈在**泛化**——150 张训练图不足以支撑 0.85 的泛化水平。

继续加模型的收益已明显递减：每增加一个模型约 +0.004，
按此推算 5~6 个模型约 0.845，仍难稳定过线。

**建议（按性价比排序）：**
1. **补充人工标注**——最有效。每张再补 2~3 张同批次不同个体的图。
2. 若只能用现有数据：再训 2~3 个 GN 模型（不同 seed/depth）做集成，
   预期 ~0.845，仍不保证达标。
3. 与需求方确认 Dice 口径：当前是「全分辨率 GT 比对」。
   若改用 ÷2 口径，分数会自然升高但信息量下降，不建议。

### 关键工程约定
- **断点续训必备**：本机会过夜休眠冻结训练进程（已踩坑两次），
  训练脚本保存 model/opt/sched/EMA 全部状态
- **评估必须分块**：整批 40 张 552x688 单层激活即 1.8GB 直接 OOM；
  分块大小按像素预算自适应
- **GroupNorm 显存**：base32/depth4 @batch8 峰值 8.37GB > 8GB 上限，
  GN 必须 batch<=4（BN 同配置可跑 batch8）
- **GPU 任务不可并发**，跑训练前先确认无其他 python 进程
- 掩码上采样**必须 INTER_NEAREST**（÷4 口径 0.9699 vs linear 0.9274）
